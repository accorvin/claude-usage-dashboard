# Claude Code Token Usage Dashboard

A local web dashboard to visualize token usage across all your Claude Code sessions — broken down by model and day.

![Dashboard screenshot showing stacked bar chart and token breakdown](https://raw.githubusercontent.com/accorvin/claude-usage-dashboard/main/screenshot.png)

## What It Shows

- **Stacked bar chart** — tokens by day (input, output, cache write, cache read)
- **Donut chart** — total token breakdown by type
- **Session table** — per-session detail with totals row
- **Model cards** — aggregate stats per model
- **Filters** — select model(s) and date range to slice the data

## Requirements

- Python 3.8+
- Claude Code installed (data lives in `~/.claude/projects/`)

## Setup

```bash
git clone https://github.com/accorvin/claude-usage-dashboard.git
cd claude-usage-dashboard
pip install -r requirements.txt
```

## Running

```bash
python app.py
```

Then open [http://localhost:5050](http://localhost:5050) in your browser.

The app reads directly from `~/.claude/projects/**/*.jsonl` — no config needed. It picks up all sessions automatically.

## Running the Tests

The test suite uses Playwright to verify the dashboard in a real browser.

```bash
pip install pytest pytest-playwright
playwright install chromium
pytest tests/ -v
```

## Data Source

Claude Code stores session transcripts as JSONL files under `~/.claude/projects/`. Each file is one session. The app parses the `message.usage` fields for token counts and `message.model` for the model name.

No data leaves your machine — everything runs locally.

## Token Types

| Type | Description |
|---|---|
| **Input** | Fresh input tokens sent to the model |
| **Output** | Tokens generated by the model |
| **Cache Write** | Tokens written to the prompt cache (charged once) |
| **Cache Read** | Tokens read from cache (much cheaper than fresh input) |

High cache read counts are normal and indicate efficient caching — you're saving money vs. sending full context on every API call.
